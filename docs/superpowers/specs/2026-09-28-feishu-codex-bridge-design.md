# 飞书 Codex 本地桥接设计

## 1. 背景与目标

本项目为个人使用场景提供一个运行在 macOS 上的本地桥接服务。用户通过飞书自建应用机器人与本机 Codex 交互，并能够在多个预先注册的本地项目之间切换。

系统只允许一个明确配置的飞书用户使用。当前项目目录内的常规开发操作自动执行；扩大访问范围、修改外部状态或可能造成数据丢失的操作必须由用户在飞书中明确授权。

MVP 的目标是验证以下闭环：

1. 飞书私聊消息能够可靠传入本机。
2. 消息能够路由到选定项目的 Codex 会话。
3. 普通开发任务可以自动执行并返回进度与结果。
4. 高风险操作可以通过飞书审批，并且授权范围精确、短期、不可重放。
5. 服务重启后能够恢复项目选择和会话映射。

## 2. 范围

### 2.1 MVP 包含

- 飞书自建应用机器人，通过官方长连接接收事件。
- 仅处理白名单用户发起的私聊文本消息。
- 多个本地项目的注册、查看和切换。
- 每个项目独立的 Codex 活跃会话。
- 通过 Codex CLI 非交互模式执行任务并解析 JSONL 事件。
- 常规操作自动执行，高风险操作通过飞书卡片审批。
- 本地 SQLite 状态持久化。
- 本地日志、敏感字段脱敏和基本运行诊断。
- 开发阶段手动启动；稳定后可选安装为 macOS LaunchAgent。

### 2.2 MVP 不包含

- 群聊或多人权限模型。
- 图片、语音、文件等非文本输入。
- 网页管理后台。
- 云端部署和多机器调度。
- 在聊天中动态注册任意项目路径。
- 公共插件市场发布。

## 3. 技术选择

- **语言：** Python。
- **飞书接入：** 飞书官方 Python SDK 和长连接事件订阅。
- **Codex 接入：** Codex CLI，使用非交互执行、JSONL 事件和 thread 恢复能力。
- **状态存储：** Python 内置 SQLite 支持，不运行独立数据库服务。
- **配置格式：** TOML。
- **后台运行：** 开发阶段手动运行；稳定后提供可选的 macOS LaunchAgent 安装方式。
- **Codex 插件：** 作为薄封装，承载安装、配置、状态检查以及 PreToolUse、PermissionRequest、PostToolUse 策略 Hook；消息桥接进程独立常驻。

选择 Codex CLI 而非直接使用 SDK，是为了优先复用本机已有的 Codex 登录、配置、Skills、沙箱和项目环境。若后续需要更丰富的实时控制，再评估迁移到 SDK 或 App Server 协议。

## 4. 总体架构

```text
飞书私聊
   │ 消息事件 / 卡片回调
   ▼
FeishuAdapter
   ▼
AuthGate
   ▼
CommandRouter
   ├── 管理命令 ──────────────┐
   └── 自然语言任务           │
            ▼                 │
      ProjectRegistry         │
            ▼                 │
        CodexRunner           │
            ▼                 │
      ResponseRenderer ◄──────┘
            │
            ▼
          飞书

横切能力：StateStore、ApprovalManager、日志与脱敏
```

### 4.1 组件职责

#### FeishuAdapter

- 建立并维护飞书长连接。
- 解析私聊文本消息和审批卡片回调。
- 调用飞书消息接口发送文本、进度和卡片。
- 不包含项目管理或 Codex 业务逻辑。

#### AuthGate

- 在任何命令或任务执行前校验发送者 `open_id`。
- 仅允许配置文件中的用户。
- 对非白名单用户不调用 Codex，也不泄露项目或服务信息。

#### CommandRouter

- 区分 `/` 开头的管理命令和普通自然语言任务。
- 校验命令参数并返回一致的用户错误。
- 将管理命令交给项目或会话服务，将普通消息交给 CodexRunner。

#### ProjectRegistry

- 从配置文件加载项目别名和绝对路径。
- 启动时解析真实路径并验证目录存在。
- 确保所有任务只能选择预先注册的项目。
- 维护当前项目选择，但不负责保存状态。

#### CodexRunner

- 为项目创建或恢复 Codex thread。
- 在项目目录中启动 Codex CLI 子进程。
- 解析 JSONL 事件，输出统一的任务事件模型。
- 支持中断、超时和异常退出处理。
- 同一时刻最多运行一个任务，避免并发修改工作区。

#### ApprovalManager

- 接收 PermissionRequest Hook 提交的高风险操作。
- 保存待审批记录并生成飞书交互卡片。
- 验证审批者身份、审批状态和有效期。
- 创建与具体操作绑定的一次性授权。
- 对过期、重复、内容变化或无法验证的请求默认拒绝。

#### StateStore

- 使用 SQLite 事务保存项目选择、thread 映射、消息去重、任务和审批状态。
- 隐藏数据库细节，为上层提供窄接口。
- 不保存飞书 App Secret 或 Codex 凭据。

#### ResponseRenderer

- 将统一任务事件转换为飞书文本或卡片。
- 合并过于频繁的进度事件，避免刷屏和触发限流。
- 对过长结果仅发送摘要，并指明本地日志位置。
- 对所有外发错误进行敏感信息清理。

## 5. 消息与会话流程

### 5.1 普通任务

1. FeishuAdapter 收到私聊消息。
2. AuthGate 校验用户身份。
3. StateStore 使用飞书 `message_id` 做幂等检查。
4. CommandRouter 将普通文本识别为 Codex 任务。
5. ProjectRegistry 提供当前项目的受信任绝对路径。
6. CodexRunner 读取当前项目的活跃 thread；不存在时创建新 thread，存在时恢复。
7. 系统立即回复任务已开始，并记录运行状态。
8. CodexRunner 解析执行事件，ResponseRenderer 以受控频率发送进度。
9. 任务结束后保存 thread 和最终状态，并发送结果摘要。

一条消息只有在成功登记幂等记录后才可启动任务。收到重复事件时返回已有任务状态，不重复运行 Codex。

### 5.2 管理命令

```text
/projects              查看已注册项目
/use <项目名>          切换当前项目
/current               查看当前项目、Git 分支和会话
/new                    为当前项目创建新的活跃会话
/resume                 查看并恢复当前项目的历史会话
/stop                   中止当前运行任务
/help                   查看帮助
```

规则：

- 项目名称只能来自配置文件。
- 切换项目不销毁原项目会话。
- `/new` 只替换当前项目的活跃 thread 映射。
- `/stop` 优先于其他命令；先请求温和终止，超时后终止子进程。
- 有任务运行时，除 `/stop` 和只读状态命令外，不接受新的执行任务。
- 第一版每个项目只维护一个活跃 thread，同时保留可恢复的历史记录。

## 6. 安全与审批

### 6.1 默认沙箱

Codex 在当前项目目录下以 `workspace-write` 沙箱运行，审批策略使用 `on-request`。项目路径在启动时固定，聊天消息不能改变工作目录或添加新的允许目录。

默认自动执行：

- 读取、搜索和修改当前项目内文件。
- 在当前项目内创建文件。
- 运行测试、构建、格式化和静态检查。
- 查看 Git 状态、分支和差异。
- 在沙箱允许范围内运行普通命令。

必须审批：

- 访问或修改当前项目之外的路径。
- 删除重要文件或执行批量删除。
- 执行可能丢失工作的 Git 操作，例如强制重置、清理或覆盖。
- `git push`、发布、部署或向外部服务写数据。
- 读取钥匙串、凭据或敏感配置。
- 安装系统级软件、修改系统配置或管理无关进程。
- 扩大沙箱权限或执行无法可靠归类的操作。

### 6.2 非交互审批限制与策略覆盖

Codex CLI 非交互执行不会直接等待外部用户审批；未被 Hook 决定的审批请求会被拒绝。因此系统使用 Hook 和两阶段重试，不假设 CLI 能够原地等待飞书回调。

PermissionRequest 只会在 Codex 已准备请求权限时触发。为确保当前项目内可能直接执行的破坏性操作也被拦截，插件同时注册 PreToolUse：它只对明确的高风险规则作出阻止决定，常规操作不返回决定。PostToolUse 用于在工具执行后原子地消费授权。未知或无法稳定解析的高风险输入失败关闭。

### 6.3 两阶段审批流程

1. Codex 准备调用工具。PreToolUse 检查明确的高风险规则；需要扩大沙箱权限的操作随后还会触发 PermissionRequest。
2. 命中的策略 Hook 把规范化后的操作、事件类型和当前 turn ID 提交给本地桥接服务。
3. 如果不存在匹配的一次性授权，Hook 拒绝本次操作，并创建待审批记录；常规 PreToolUse 调用不作决定。
4. ApprovalManager 向飞书发送包含操作摘要、项目和有效期的审批卡片。
5. 用户点击批准或拒绝；服务再次验证 `open_id`。
6. 批准时，服务创建一次性授权，并恢复同一 thread，要求 Codex 重试被拒绝的操作。
7. Hook 仅在操作内容与授权完全匹配时放行，并把授权绑定到当前 turn。若同一工具调用随后触发 PermissionRequest，同一授权可以在同一 turn 内继续通过。
8. PostToolUse 在操作完成后原子地把授权标记为已消费。服务或 Codex 在执行中断开时，处于执行中的授权不可用于新的 turn，并在过期后关闭。
9. 拒绝时，服务恢复 thread，并明确告知 Codex 用户拒绝了该操作，不得换用等价方式绕过。

一次性授权至少绑定：

- 项目 ID 和规范化工作目录；
- Codex thread ID；
- 工具名称；
- 规范化后的工具输入摘要与内容哈希；
- 审批用户的飞书 `open_id`；
- 创建时间和过期时间；
- 唯一 nonce；
- 已消费状态。

任何内容变化、授权重放、超时、服务重启期间的不确定状态或解析失败都必须拒绝。

## 7. 配置、状态与凭据

### 7.1 配置示例

```toml
[feishu]
allowed_open_ids = ["ou_xxx"]

[projects.feishu-bridge]
path = "/Users/example/workspace/feishu_codex_bridge"
default = true

[projects.other-project]
path = "/Users/example/workspace/other-project"

[codex]
sandbox = "workspace-write"
approval_policy = "on-request"
```

`config.toml` 保存人工维护的非敏感配置。启动时必须校验：

- 恰好有一个默认项目。
- 项目别名唯一且符合命令参数约束。
- 路径为存在的目录，并能解析为稳定的真实绝对路径。
- 项目路径不能通过符号链接逃逸到另一个注册范围。
- 白名单至少包含一个合法的 `open_id`。

### 7.2 SQLite 状态

SQLite 至少保存以下逻辑实体：

- `projects_state`：项目当前选择和运行状态。
- `threads`：项目与 Codex thread 的关联及历史。
- `messages`：飞书消息幂等状态和对应任务。
- `tasks`：任务生命周期、时间戳、退出结果和错误摘要。
- `approvals`：待审批请求、决定、有效期和一次性消费状态。

数据库文件放在用户级应用数据目录，不写入被操作的项目仓库。涉及任务、消息和会话映射的状态变化应放入同一事务，避免部分写入。

### 7.3 凭据与日志

- 飞书 App ID 可写入配置。
- 飞书 App Secret 通过环境变量或 macOS 钥匙串提供，不进入 Git、SQLite 或普通日志。
- Codex 复用本机已有认证，不复制或导出认证材料。
- 日志统一清理令牌、密钥、Authorization 头和常见敏感字段。
- 日志文件轮转并限制保留量。

## 8. 后台运行

开发阶段通过前台命令手动启动，便于观察日志和调试。功能稳定后提供可选 LaunchAgent：

- 当前用户登录后自动启动。
- 异常退出后按受控策略重启。
- 标准输出和错误输出写入指定日志文件。
- 提供安装、卸载、启动、停止和状态检查命令。
- 仅以当前登录用户身份运行，不安装 root LaunchDaemon。

电脑休眠、关机或用户未登录时，机器人不可用。恢复后重新建立飞书长连接，但不自动重放中断任务。

## 9. 异常处理

- **飞书断线：** 指数退避重连；依赖消息幂等记录避免重复执行。
- **Codex 异常退出：** 保存最后事件和退出状态，向飞书发送脱敏摘要。
- **任务超时：** 请求终止子进程，超时后强制结束；不自动重试写操作。
- **服务重启：** 将仍处于运行态的任务标记为已中断，由用户决定是否重新发起。
- **回复失败：** 有限次数重试；持续失败后写本地日志并停止重试。
- **数据库错误：** 当前消息不启动 Codex，避免失去幂等和审计状态。
- **审批异常：** 一律失败关闭，不产生宽泛或长期授权。
- **事件无法识别：** 记录脱敏诊断，不把原始内部事件直接发送到飞书。

## 10. 测试策略

### 10.1 单元测试

- 用户白名单校验。
- 管理命令解析和错误信息。
- 项目真实路径、符号链接和别名校验。
- 危险操作分类。
- 一次性授权的匹配、过期、消费和防重放。
- 消息去重和状态转换。
- 日志脱敏。

### 10.2 集成测试

- 使用假的 FeishuAdapter 和假的 Codex 子进程验证完整消息流程。
- 验证新建 thread、恢复 thread、项目切换和任务中断。
- 验证飞书消息重投不会重复执行任务。
- 验证高风险操作第一次被拒绝、批准后仅放行一次。
- 验证服务重启后的状态恢复和中断任务处理。

### 10.3 CLI 契约测试

- 使用固定 JSONL 样本验证事件解析。
- 在可用的本机 Codex CLI 上运行最小烟雾测试，验证 thread ID、退出码和错误事件。
- 将未知事件视为向前兼容输入：记录但不崩溃。

### 10.4 手工验收

- 真实飞书私聊收发。
- 多项目查看与切换。
- 同一项目的连续上下文。
- 普通文件修改和测试执行。
- `/stop` 中断长任务。
- 高风险操作的批准、拒绝、过期和重复点击。
- 断网重连和服务重启。

## 11. MVP 完成标准

MVP 只有在以下条件全部满足时才算完成：

- 白名单用户可以通过飞书私聊使用机器人，其他用户无法触发 Codex。
- 用户可以查看并切换多个预先注册的项目。
- 每个项目维持独立的活跃 Codex thread。
- 常规开发任务能够自动修改项目、运行测试并返回结果。
- 高风险操作未经批准不能执行；批准精确绑定操作且不可重复使用。
- 重启服务后，当前项目和会话映射仍然存在。
- 重复飞书事件不会造成任务重复执行。
- 项目提供配置示例、启动停止说明、测试说明和可选 LaunchAgent 安装方式。

## 12. 后续演进

在 MVP 稳定后，可按实际需要考虑：

1. 从 Codex CLI 迁移到 SDK 或 App Server 协议，以获得更直接的实时事件和审批控制。
2. 支持飞书文件、图片和富文本输入。
3. 支持受控群聊和多人角色权限。
4. 提供本地菜单栏状态界面。
5. 完善插件打包并评估私有或公共分发。

这些能力不进入当前实现计划，除非 MVP 验证表明其为核心闭环所必需。
